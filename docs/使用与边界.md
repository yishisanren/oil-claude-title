# oil-claude-title 使用与边界

让 Claude Code 会话列表里的名称跟上实际讨论内容。

每轮对话结束后，插件在后台读取最近 3～5 轮有效对话与原始目标，由独立模型判断是否更新标题。标题使用「类别 emoji + 对象｜目标」，准确时保持原样。外层项目已提供名称时，标题默认省略重复项目名；monorepo 子项目、上级目录操作或跨项目歧义除外。

## 工作原理

1. **触发**：插件注册一个 `Stop` Hook（`hooks/hooks.json`，`async: true`）。每轮回答结束后宿主把事件 JSON 写给 `scripts/oil_claude_title.py hook`。Hook 进程只校验事件、派生一个独立进程组的后台 Worker，然后立刻返回空 JSON `{}`，不向对话返回任何文字。
2. **读取**：Worker 按事件里的 `transcript_path` 只读解析会话记录（JSONL）。只取用户的真实请求和每轮最后一段助手正文；工具调用与结果、思考、子代理旁支、宿主注入的命令回显、Skill 正文、系统提醒都不进入命名上下文。当前标题取记录里最后一条 `custom-title`（宿主读取时同样 last-wins）。
3. **命名**：用 `claude -p --safe-mode --model haiku --tools "" --no-session-persistence --json-schema … --system-prompt-file prompts/naming.md` 启动一个隔离的临时模型进程：复用当前登录，不加载 Hook、插件、CLAUDE.md 与 MCP，不保存会话，不允许任何工具。默认关闭扩展思考（`MAX_THINKING_TOKENS=0`），实测 haiku 单次 6～10 秒。
4. **写入**：候选通过格式校验后，向会话记录追加一行 `{"type":"custom-title","customTitle":…,"sessionId":…}`，与 `/rename` 写入的记录格式完全一致；不改写、不删除既有内容。写入后读回核验。
5. **采纳**：Claude Code 读取会话标题时取最后一条 `custom-title`；运行中的会话在下一次重写会话元数据时会先读文件尾部的 `custom-title` 并采纳（依据 2.1.266 可执行文件内逻辑，并用存活两轮的真实会话验证：第二轮没有覆盖插件写入的标题）。Claude 桌面版另有自己的标题缓存：侧边栏按缓存显示，并会在新一轮提问时把缓存的标题写回记录（2026-09-16 实测，两个运行中的桌面会话在后台改名后于下一轮被写回旧标题）。插件把「写回改名前的旧标题」识别为宿主行为而不是用户改名：第一次记录 `host_reverted` 并继续，第二次以「宿主反复写回旧标题」锁定。要让桌面侧边栏跟上，需要在会话内执行 `/oil-title apply`，它会在写入后调用桌面版的 `set_session_title` 同步缓存；批量整理历史会话时同样由会话内的 Claude 调用该工具。

## 安装与开始使用

需要 Python 3.9+ 和已登录的 Claude Code CLI（2.1.266 实测）。无需另外保存 API Key；命名消耗当前账号的模型额度。

```sh
claude plugin marketplace add yishisanren/oil-claude-title      # 或本地目录路径
claude plugin install oil-claude-title@oil-claude-title
```

安装写入 user 范围的 `enabledPlugins`，对所有项目生效；只在**新开的**会话里加载。验收步骤：

1. 新会话里执行 `/oil-title doctor`：`version` 为 Claude 版本，`hook.status` 为 `ready`。
2. 正常聊几轮，等待约 15 秒后查看数据目录 `logs/<会话 ID>.jsonl` 是否出现 `renamed` 或 `kept` 记录，这是 Hook 真实触发的证据；`doctor` 通过不能代替它。
3. 在 `claude --resume` 列表里确认标题；桌面版侧边栏需另行确认。

临时验证可用 `claude --plugin-dir <插件目录>` 只对当前会话加载插件，不写入任何配置。

## 命名方式

标题固定为「emoji 对象｜目标」：对象在前，目标在后，恰好一个全角分隔符。类别按持续产物选择，不随“修复”“发布”等临时动作切换。旧标题允许一次结构迁移，之后保留准确的对象措辞和主线；信息不足或已锁定时保留原名。

标题跟随最近几轮用户实质需求的主要语言，保留产品名和技术名词；助手回答、代码及引用原文不决定标题语言。偶尔一句外语不切换，持续换用另一种语言后允许迁移。语言判断由同一次命名完成，不额外调用语言检测模型。

| 类型 | emoji |
| --- | --- |
| 内容制作 | 🎬 |
| 工具开发 | 🧩 |
| 对比调研 | 🔎 |
| 方法整理与文档 | 📝 |
| 日程安排 | 📅 |
| 页面设计 | 🎨 |
| 环境配置 | ⚙️ |
| 一般讨论 | 💬 |

默认参考最近 5 轮有文字的对话。只有问候或确认且没有实质目标时，直接保留标题，不调用模型。临时排错、术语解释、测试或「继续」不会自动变成新的主要目标。命名规则集中在 `../prompts/naming.md`。

## 控制方式

会话内用 `/oil-title <动作>` 或自然语言（由插件 Skill 处理）。也可以在插件目录中直接运行程序；在 Claude Code 会话的 Bash 里运行时会自动读取 `CLAUDE_CODE_SESSION_ID`，在普通终端里需要显式给出会话 ID：

```sh
python3 scripts/oil_claude_title.py doctor [--session <会话ID>]
python3 scripts/oil_claude_title.py status
python3 scripts/oil_claude_title.py configure --model haiku --thinking off --effort low
python3 scripts/oil_claude_title.py configure --model sonnet
python3 scripts/oil_claude_title.py configure --claude-bin <路径>
python3 scripts/oil_claude_title.py rename [<会话ID>]            # 只预览
python3 scripts/oil_claude_title.py rename [<会话ID>] --apply    # 写入并读回核验
python3 scripts/oil_claude_title.py lock [<会话ID>]
python3 scripts/oil_claude_title.py unlock [<会话ID>]
python3 scripts/oil_claude_title.py pause
python3 scripts/oil_claude_title.py resume
```

`rename --apply` 会向会话记录追加标题行。auto 权限模式的分类器可能把这类命令当作修改会话记录而拦截；此时改用宿主自带的 `/rename`，或为该脚本添加 Bash 权限规则。后台 Hook 不经过分类器。

配置项（`config.json`，未知字段保留）：`model`（默认 `haiku`）、`effort`（`low`）、`thinking`（`false`）、`claude_bin`、`recent_turns`（3～5）、`max_context_chars`、`model_timeout_seconds`（10～110）、`max_parallel_workers`（1～8）、`max_budget_usd`（单次模型调用上限，默认 0.2）。

## 数据与并发边界

配置、每会话状态和简短日志默认位于 `~/.claude/oil-claude-title`（尊重 `CLAUDE_CONFIG_DIR`）；`OIL_CLAUDE_TITLE_DATA` 可指定独立目录，测试时用它避免污染真实数据。

对话摘录仅传给当前登录账号使用的模型服务，不向其他服务发送。插件不保存完整对话或命名提示词；临时模型进程不留会话记录。持久日志只记录状态、候选标题、简短理由与用量，每个会话按容量轮转。

同一会话使用内核文件锁；新 Hook 最多等待两个模型超时窗口加 20 秒，释放锁后重新判断最新轮次。不同会话共享 `max_parallel_workers` 个并发额度，排队时间算入模型预算。重复内容跳过模型调用；临时模型进程用 `--safe-mode` 并设置 `OIL_CLAUDE_TITLE_WORKER=1`，双重避免递归。同工作目录中发现与已记录标题重名时最多额外生成一次，仍冲突就返回 `ambiguous_title`。写入前重新读取会话，如果标题或对话已变化，就丢弃旧结果。会话记录没有原子条件写入，最后一次检查与追加之间仍有极短的并发窗口。

插件成功完成一次评估或写入后才建立稳定基线；此后检测到外部改名（包括 `/rename`）会自动锁定。首次处理前无法区分宿主自动标题与用户手动标题，需要保留的标题请主动 `lock`。暂停或锁定不会取消已产生的模型费用。

## 兼容性与限制

- macOS：实测。优先使用宿主通过 `CLAUDE_CODE_EXECPATH` 提供的可执行文件，其次 PATH 中的 `claude`。
- Linux：保留 POSIX 内核锁，仅单元测试覆盖。
- Windows：单元测试覆盖锁与编码；需要原生 `claude.exe`（`claude install`），npm 的 `.cmd` 入口会被拒绝。`hooks.json` 里的 `python3` 可能需要改成 `py -3`。未实测。
- `claude -p` 一次性会话：进程打印结果后立即退出，异步 Hook 被一并结束，不会命名。
- 云端会话、企业远程存储后端：不支持，插件只会读写本地 JSONL。
- 会话记录格式是 Claude Code 内部格式，可能随版本变化；插件只依赖 `custom-title` 一行的形状和 `user`/`assistant` 记录的基本字段，`doctor --session` 可验证当前版本能否读取。
- 插件只响应安装之后实际触发的轮次，不自动扫描或批量修改历史会话。
- Claude 桌面版：后台改名不会更新侧边栏缓存，且会被下一轮提问写回；桌面会话请用 `/oil-title apply`，或让会话内的 Claude 批量调用 `set_session_title`。CLI 与 `/resume` 不受影响。
- 原版的闲置话题归档没有移植：Claude Code 没有归档接口。

## 与原版的差异

| 项目 | oil-codex-title | oil-claude-title |
| --- | --- | --- |
| 触发 | Codex Stop Hook | Claude Code Stop Hook（async），Hook 进程再派生后台 Worker |
| 读取对话 | App Server `thread/read` | 只读解析会话记录 JSONL |
| 写入标题 | App Server `thread/name/set` | 追加 `custom-title` 记录行（与 `/rename` 相同） |
| 命名模型 | `codex exec` + GPT-5.6 Luna Fast | `claude -p --safe-mode` + haiku（可 `configure --model` 更换） |
| 结构化输出 | `--output-schema` | `--json-schema` + `structured_output` |
| 归档 | 支持 | 未移植 |
| 桌面显示 | `set_thread_title` 同步 | Skill 可用宿主的 `set_session_title` 工具同步（用户明确要求时） |

## 开发验证

```sh
python3 -m unittest discover -s tests -v
python3 scripts/evaluate_naming.py            # 只统计案例数
python3 scripts/evaluate_naming.py --live     # 实际调用账号模型，写 docs/naming-evaluation.json
```

真实自动触发需要在已安装插件的新会话里验证；直接运行 `hook` 命令只验证处理链路。

2026-09-16 在 macOS、Claude Code 2.1.271、haiku（effort low、关闭思考）上的一次评测：30 个合成案例通过 29 个，中位 9.0 秒，合计约 0.32 美元等值额度；未通过的是跨项目同步案例（标题漏掉目标项目名）。结果见 `naming-evaluation.json`，单次样本不代表普遍准确率。
